# 俯视高度图、大模型作用与项目意义

本项目研究的是：**怎样让大模型通过有限的、与任务有关的视觉观察，对大规模三维点云作出可追溯的标注决定。** 电线是当前的验证任务。代码把观察选择与点云执行分开，而不是把所有原始点写成模型输入。

## 电线从哪里被发现？

当前五条主线的发现和横向分离主要来自俯视投影。全场景真实动作记录中：

- `LOOK initial_top` 生成完整ROI的俯视图。
- 随后的 `LOOK wire_1_side` 等动作记录理由：俯视图出现五条分开的近似平行轨迹；对明确选中的轨迹请求侧视，检查弧垂、地面与支撑混入。
- `PROPOSE full_wire_*` 明确指定俯视路径与侧视路径的共同约束，并保留接触处的未知窄带。

这些记录可在 `demo/audit/index.html` 的全场景分支中查看。塔旁局部补标还在俯视标记图中显式关联 A1→B1→C1→D1→E1，再换侧视分开导线、绝缘子与塔架。

严格来说，当前 `height` 图是**带高程信息的点云正交投影**。XY决定俯视图位置，Z影响亮度。每像素选从上方可见的最高原始点；深度图和像素到原始点的映射保存在执行器中。VLM看到的是PNG，不是另一个单独的深度通道。投影没有语义标签，也不是地面DEM，更不保存同一像素下的所有高度层。

因此，可以说“从俯视高度图看电线”，但不应把它讲成已经把三维信息完整压入一张图，或把高度亮度等同于电线类别。

## 大模型承担哪一部分？

| 环节 | 可得到的几何证据 | 观察者需要判断的内容 |
|---|---|---|
| 俯视发现 | 高处细长轨迹的位置与延伸 | 哪些轨迹对应任务中的电线；如何区分相邻实例 |
| 侧视消歧 | 高程变化、弧垂、与支撑的相对位置 | 哪些片段对应同一条线；哪些应排除或暂留未知 |
| 主动观察 | 新视角与局部放大可被请求 | 当前缺少什么证据；下一步从哪里看 |
| 候选复核 | 原始邻域、候选叠加、可见性信息 | 支持、矛盾或看不清；提交、撤回还是改选 |
| 三维落点 | 保留的坐标、深度、原始记录ID | 模型明确指定选区；执行器负责映射与一致性检查 |

渲染器使电线**可见**，但没有预先判定“这是电线”或自动完成跨片段追踪。局部测量工具只提供坐标和独立行列内的点簇。记录中的关联、路径、选区、未知范围和提交决定来自会话视觉观察者。

另一方面，本项目也依赖几何渲染、选区映射、可见性计算和原始点校验。当前没有对照证明大模型不可替代，也不能把全部成功都归因于模型本身。

## 工作的意义是什么？

第一，为现有视觉大模型提供一个**可观察、可操作、能返回原始点ID的三维点云接口**。模型通过空间图像理解任务，执行器保存数据的精确身份。这使图像上的语义判断可以形成三维点标注，而不只是输出一段文字解释。

第二，把“点云过大”转成“应该观察哪些图像”的问题。这里压缩的是送入模型的观察量；完整原始点仍在本地。单视图丢失或混叠的信息，通过任务驱动的换角度与局部观察补充。模型可以先看全局形状，再将观察预算花在接触、交叉和身份不清的区域。

第三，让观察、语义判断和结果之间可追溯。对一个已标点，应能找到选区、原始图像、观察理由和提交记录；有矛盾时可以撤回，有歧义时保留未知。未知目标点仍进入召回分母，避免只展示漂亮的选中结果。

合理的项目表述是：**基于任务驱动多视角视觉观察的三维点云标注接口与原型。** “利用空间关系实现任务型点云观察压缩”是研究方向；目前还不能说已经证明了通用压缩方法、最优token效率或人类认知等效。

## 当前证据能支持什么？

全场景开发结果P=99.9894%、R=97.3826%，表明这次保存的会话视觉决定能落到高质量的原始点语义标注，且执行、回放与导出一致。它尚未单独证明模型的净贡献：

- 没有仅俯视、固定多视角、主动多视角与几何方法的等条件对照。
- 没有量化图像/观察/token预算与精度、时延的权衡。
- 没有独立留出场景、无人值守重复成功率或逐线完整性验收。

这些问题属于后续科学验证。本轮演示说明模型在记录中做了什么，不能把“参与了判断”扩大成“已经证明优于其他方案”。
